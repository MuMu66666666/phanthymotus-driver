# G1 站岗哨兵：1.1.0 警告调试版

这次修复只恢复距离警告的调试基础，不表示原定“后退与转身”已经通过真机验收。

## 真机问题与证据

2026-09-23 调试时，只读状态报告 fsm_id=0、zero_torque、posture=squat、loaded=false。机器人没有处于平衡控制状态。此前 move 的 ret=null 和 duration_expired 只能说明调用/计时结果，不能证明机器人走动。

传感器实际输出字段是 distance_m，不是 distance。当前驱动使用画面中心单点深度，无法据此确认“人”。零深度可能来自无效深度，不能解释为人离开。机器人蹲着时约 0.7 米的稳定读数也不能证明有人靠近。

后台监控通过语言模型推理，日志中有数秒延迟及 `400 No user query found in messages`。本修改没有修复平台模型适配层，也不保证实时反应。

## 当前调试行为

只允许距离报告、灯光和语音，不自动起身、后退、转身或切换模式。instruction 中的限制不是底层运动权限隔离，不能作为机器人安全控制器。

有效输入要求 distance_m 为有限正数、样本接收时间可信且距当前不超过 2 秒，至少三个独立样本覆盖 0.2 秒。没有这些证据时只报告数据不足。

- 小于 0.15 米：疑似镜头前近物，红灯和距离提示。
- 0.15 至小于 0.8 米：近物警告。
- 同一事件只提示一次，至少 5 秒冷却；有效读数大于 1 米持续满足采样要求才重新布防。
- 零值、无效值和断流不解除警戒，也不代表有人离开。

红灯为常亮，未实现闪烁。单点深度不能确认人或镜头遮挡。这些规则在独立组件中有测试；仅更新 instruction 不等于接入确定性控制循环。

## 下一阶段

1. 现场负责人按设备操作规范完成起身与平衡控制准备，确认设备、场地、急停及后方空间。不让初学者试发模式切换或起身命令。
2. 保持运动禁用，确认实际距离数据有新鲜时间信息；用安全距离的目标验证读数、无效深度、警告及解除。不需要用手贴住镜头。
3. 在平台适配层定位空用户消息的 400 错误；将纯规则组件接入传感器事件循环，保存采样和触发时间，测量真实延迟。语言模型负责开启/退出和解释，不承担每帧判定。
4. 恢复运动前实现独立门禁：有效平衡状态、数据新鲜、后方空间验证、最大单次动作、冷却、取消/超时停止；缺少任何条件均不移动。前置单点深度无法证明后方安全，失去视觉时也不能直接转身。
5. 在负责人监督下分别验收移动、停止、异常中止，再联调哨兵并留存实际结果。未完成前不宣称 landing 真机任务通过。
