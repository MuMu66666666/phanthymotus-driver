# G1 交接班助手

`g1-shift-handover` 1.0.0：读取姿态和模式，把设备返回与用户陈述分开整理，用户确认后输出可复制的交接记录。不依赖相机、距离流或后台监控，不执行运动。

## 文件与验证

- `install_g1_shift_handover.py`：Skill 定义及离线 SQLite 安装器，新安装默认禁用；备份原数据库，保留其他技能和配置。
- `g1_shift_handover.json`：同版本定义的导出文件，供审核和发布填写。
- `test_install_g1_shift_handover.py`：安装、备份、重复安装及错误配置保护的数据库回归测试。

运行：`python -m unittest discover -s unitree/g1/scripts -p test_install_g1_shift_handover.py -v`。

本地数据库测试不能证明模型遵循指令、设备状态新鲜或真机验收通过。当前真机流程待验证。

## 部署前提

先确认目标机器人、画布连接、`posture` 工具和 `switch_mode` 的只读 `get_current_mode` 动作。接口失败时报告未知，不自动修改模式。

离线安装应在 agent-core 停止、实际数据库路径确认且自动启动智能控制关闭后执行：

```sh
python3 install_g1_shift_handover.py --db /实际确认的路径/data.db
```

安装器输出备份位置；安装失败时不要覆盖数据库继续尝试。重启 agent-core 后从技能列表读取并核对版本和 instruction，然后启用本技能。不要使用“更新全部服务”作为安装步骤。

`switch_mode` 本身也有控制动作，instruction 的只读要求不是权限隔离。联调时保持旧站岗技能禁用，不连接旧站岗、相机和移动控制链；先核查实际画布、工具权限与调用日志，再启用本次对话。无需机器人起身。可选语音在文字流程通过后单独验证。

## 零基础验收步骤

1. 在连接正常且本技能已启用的画布中输入“准备交接”。应只读取姿态、模式，并询问本班工作、问题、下班待办。
2. 输入：“今天测试交接助手；我观察到相机断流；下一班检查相机数据线。”应输出待确认草稿。相机问题必须标为用户报告，不能写成助手检测结论。
3. 输入：“把下一班待办改成先联系设备负责人。”应修改草稿并再次请求确认。
4. 输入：“确认交接。”应输出已确认记录供复制保存；不声称已上传、发给老师或保存文件。
5. 另起一次交接，输入“取消交接”。应结束，不提交、不播报、不恢复旧站岗。
6. 在隔离测试配置中使状态工具不可用，验证报告标为未知仍可交接。不要为了此用例拔线或中断真实机器人服务。
7. 可选：确认记录后要求“播报简短摘要”。现场确认是否听到；无可用语音工具也可完成文字交接。

保存实际提示、返回文本、工具调用日志和画布截图。检查日志中没有动作切换、移动、相机启动或站岗调用。若发现越界调用则停止本轮并修正，不能仅凭文字回答判通过。
